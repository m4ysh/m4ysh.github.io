LOG 001 REWARD DESIGN / MECHANISTIC INTERPRETABILITY

Deterministic Rewards for Open-Ended Agents

Most agent benchmarks can be evaluated by a Python function. The hard part is choosing which function. This post is about why LLM-as-judge is the wrong default for open-ended agent tasks, what verifiable rewards (RLVR) actually buy you, and how the Mechatron project uses circuit F1 as a deterministic verifier for mechanistic interpretability agents.

// 01   THE PROBLEM WITH LLM-AS-JUDGE

The first time I built an agent that produced a hypothesis about a transformer's internal circuitry, I evaluated it by sending the hypothesis to GPT-4 and asking "is this correct?" The results were plausible. The agent's hypotheses were well-structured, used the right vocabulary, cited the right papers. They were also, in retrospect, largely wrong. The judge was rewarding fluency. The agent was producing fluency. Everyone was happy.

The LLM-as-judge paradigm is now standard in agent evaluation. The reasoning is straightforward: open-ended tasks (creative writing, dialogue quality, hypothesis generation) don't have a single correct answer, and scaling human evaluation is expensive. Use a strong LLM to score. It correlates with human raters, it's cheap, and it runs in seconds. The results, in the average case, are usable.

The failure modes are now well-documented. Position bias: judges systematically prefer the first or second response in a comparison, regardless of quality. Verbosity bias: longer answers score higher. Self-enhancement bias: judges rate outputs from the same model family higher. Anchoring: scores shift when the prompt is reworded, when the model is updated, or when the temperature is changed. The bias literature is extensive enough that, in 2026, deploying an LLM judge without measuring its position and length bias is professionally negligent.

The deeper problem is structural. When the judge and the generator share a training distribution, they share blind spots. The judge rewards what looks like the right answer. The generator produces what looks like the right answer. The loop converges on the joint mode of "plausible text", which is, for open-ended tasks, exactly the wrong signal. You want a signal that distinguishes "looks plausible" from "is correct." LLM judges, by construction, cannot make that distinction.

// 02   THE RLVR PIVOT

The post-RLHF consensus is that the answer is verifiable rewards: what the Tulu 3 paper (Lambert et al., 2024) named RLVR and what DeepSeek-R1 brought to global attention in January 2025. The paradigm is simple: instead of training against a learned reward model, train against a deterministic verifier that checks objective correctness. Math problems get a symbolic solver. Code gets a unit test harness. JSON outputs get a schema validator. The reward is binary (1 if the verifier passes, 0 if it doesn't), and the verifier is external, auditable, and does not require human labelers at training time.

The advantages are real. RLVR avoids the entire RLHF overoptimization problem (Gao et al., 2023), the well-known phenomenon where a learned reward model can be exploited even when its scores correlate with human preferences. The verifier doesn't have a learned failure mode. The verifier is the failure mode. If the verifier is wrong, the agent learns to satisfy the wrong thing. If the verifier is right, the agent learns the right thing. There is no gradient between.

The limits are also real. RLVR works in domains where correctness is checkable: math, code, structured output, games with clear win conditions. It works less well in domains where the answer is a judgment, an aesthetic, a hypothesis, a piece of writing. For those domains, the field has reached for two compromises. The first is process reward models (PRMs), learned verifiers that score the reasoning trace, not just the final answer. The second is LLM-as-judge, with all the documented bias problems. Neither is a true verifier. Both are useful. Both are, in the end, proxies.

The interesting design question, for any specific task, is: can the correctness signal be made deterministic? If yes, use a verifier. If no, use a judge, but measure its biases, report them, and don't treat its output as ground truth. The Mechatron project exists because, for one specific kind of open-ended task, the answer is yes.

// 03   WHY MECHANISTIC INTERPRETABILITY IS THE HARDEST CASE

Mechanistic interpretability is the practice of reverse engineering neural networks into human-understandable circuits: subgraphs of attention heads and MLPs that implement a specific behavior. The canonical example is Wang et al.'s (2022) Induction Heads circuit in two-layer attention models, or the IOI (Indirect Object Identification) circuit in GPT-2 small. These are discoveries: the model's algorithm, once found, is a verifiable fact about the weights. Either the "duplicate token head" exists at layer 9, head 6, or it doesn't. Either the IOI circuit, when ablated, drops the model's IOI accuracy to chance, or it doesn't.

The open-ended part is the process of finding the circuit. An interpretability agent runs ablation experiments, queries attention patterns, performs activation patching, and forms a hypothesis about which heads are involved. The hypothesis is open-ended. The evaluation is not. If the agent claims head 9.6 is part of the circuit, you can check by running the standard circuit faithfulness ablation: ablate head 9.6, run the model on IOI prompts, measure the accuracy drop. If the drop matches the claim, the head is in the circuit. If not, it isn't. The verifier is a few lines of PyTorch.

This is the design space where Mechatron lives. The task is open-ended. The evaluation is deterministic. You can train an agent against a verifier that doesn't share its training distribution, doesn't have position bias, and doesn't reward plausible prose. The agent learns to find real circuits, not plausible-sounding ones.

// 04   CIRCUIT F1 AS A VERIFIER

The standard circuit evaluation, after Conmy et al. (2023) and the ACDC algorithm, treats a circuit as a set of edges in the model's computational graph. The "true" circuit is the set of edges the model's computation actually depends on. An agent's hypothesis is a set of edges it claims are in the circuit. The comparison is a set comparison.

F1 is the harmonic mean of precision and recall. For circuits:

  • Precision = (claimed edges that are actually in the true circuit) / (total claimed edges). Rewards not over-claiming.
  • Recall = (claimed edges that are actually in the true circuit) / (total true edges). Rewards not under-claiming.
  • F1 = 2 · (P · R) / (P + R). A single number in [0, 1] that punishes both extremes.

Computing the components requires knowing the true circuit. Mechatron solves this by planting the ground truth. The agent operates on toy transformers (1-layer, 2-layer, 4-layer) where the circuits are constructed by the environment, not learned. The agent sees the model. The agent does not see the circuit. The environment knows the circuit. The verifier compares agent claims to environment truth and emits F1.

The planted-circuit approach is, deliberately, the opposite of the typical interpretability workflow. The typical workflow takes a real model and tries to find the circuit. The planted approach takes a known circuit and asks an agent to find it. The evaluation is unambiguous because the ground truth is in the environment. The agent cannot game the verifier by writing plausible-sounding hypotheses. The verifier checks edges. Either the edges are right or they aren't.

The F1 verifier has a false-positive penalty built in. An agent that claims every head is in the circuit has high recall and low precision. An agent that claims no heads are in the circuit has high precision and low recall. Both score near zero on F1. The agent has to commit to a hypothesis, and the hypothesis has to be right. There is no fluent middle ground.

// 05   THE MECHATRON DESIGN

Mechatron is a 11-task curriculum. The tasks are organized by difficulty. Easy tasks have small circuits in small models (1-layer attention with a 2-head induction circuit). Hard tasks have larger circuits in larger models (4-layer attention with composed behaviors). Each task plants a specific circuit. Each task gives the agent the same set of tools: ablation, attention pattern queries, activation patching, and per-head logit lens.

The reward function has three components, summed with explicit weights: 

reward = w_step · step_delta
       + w_explore · exploration_bonus
       + w_terminal · terminal_F1
       - w_fp · false_positive_penalty

The step_delta is the change in F1 between consecutive actions. This is the dense reward signal. Ablating head 9.6 and seeing F1 go up gives a positive delta. Ablating a random head and seeing F1 stay flat gives zero. The agent learns which actions move the needle.

The exploration bonus rewards actions that produce new information, not just higher F1. Querying the attention pattern on a new prompt is informative even if it doesn't immediately change the hypothesis. Without this term, the agent converges on the first locally-optimal hypothesis and stops investigating.

The terminal F1 is the F1 at the end of the episode. This is the sparse reward signal. It is the final answer. The dense signal is for learning; the terminal signal is for grading.

The false-positive penalty subtracts from the reward when the agent claims an edge that isn't in the ground truth. This is what kills the "claim everything" and "claim confidently wrong" strategies. The penalty is calibrated so that an F1 of 0.3 is worth less than an F1 of 0.5 minus the penalty for being wrong about a single edge. The agent has to be approximately right, not approximately confident.

The training was done with GRPO (Shao et al., 2024) and Unsloth on Qwen2.5-7B. GRPO is a group-relative policy optimization: the agent samples multiple rollouts per task, scores them, and updates toward the within-group winners. It is a clean fit for Mechatron because the verifier is deterministic. There is no reward model to overoptimize against, no learned biases to compound. The verifier is the verifier.

// 06   RESULTS AND LIMITS

The headline number: on expert-difficulty tasks, the trained agent improved mechanistic interpretability IOI reward from 0.355 to 0.471 in 500 steps. That is a 32% relative improvement on a non-trivial circuit-finding task, in a domain where the previous state of the art was human researchers running ablations by hand.

The interesting failures are not the ones the agent got wrong. They are the ones the agent got right in a different way than a human would. The agent finds circuits that work but don't decompose into human-interpretable modules. The F1 is high; the explanation is missing. The verifier rewards the outcome, not the story. This is a feature. It's why the agent can find circuits humans miss, but it means the agent's discoveries need to be interpreted by a human after the fact. The agent is a search engine, not a scientist.

The other limit is the toy models. Mechatron's 11 tasks use 1-, 2-, and 4-layer transformers. Real frontier-scale models are 80+ layers. The circuits in frontier models are larger, more redundant, and more entangled. The F1 verifier still works. The computational cost of running the ablation experiments scales with the number of edges. A 4-layer transformer has a few hundred edges. An 80-layer model has tens of thousands. The agent that finds a 4-layer circuit in 50 steps will need a different toolset to find an 80-layer circuit in the same number of steps. The Mechatron approach is a proof of concept, not a finished system.

The bigger lesson, though, is the verifier. F1 against a planted ground truth is the cleanest reward signal I have ever trained an agent against. There is no position bias. There is no verbosity bias. There is no plausible-but-wrong. The agent either finds the circuit or it doesn't. The reward is the same every time. The verifier is auditable in 20 lines of Python. If you can make your task's correctness checkable, do it. If you can't, use a judge, but measure it, report it, and don't pretend it's ground truth.

The environment, the verifier, and the 11-task curriculum are all at huggingface.co/spaces/nebiuz/mechatron-env. The training code and the GRPO+Unsloth notebook are in the same repository. The full task list, the ground truth circuits, and the per-task reward curves are documented in the project's README.
